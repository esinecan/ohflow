# Steer a run: the orchestrator agent's moves

You manage every run you start. Read this page when `watch`, the dashboard or a session's turn file shows an agent going wrong. It gives the moves each kind of agent allows, the two rules for making one, and the recorded failures of each box and role with the move that answers them.

## Whether a move is allowed

The objective kind decides ([campaign](campaign.md#intervention-by-kind-of-objective)). A delivery takes any move at any time. An empirical procedure takes a move only to correct a deviation, and a changed procedure restarts every arm.

## Whether a move pays

Make the move when the waiting it saves exceeds the work it throws away. Count wall time on every box: a step on the operator's own machine bills nothing and still makes the operator wait. An interrupt throws away the unfinished turn, a kill throws away one step's attempt, and stopping a run throws away every attempt in flight. An agent that starts the full suite costs about half an hour, so interrupt it and send it `run_tests.py --changed`. An agent that rereads a file costs seconds, so let it run. Log each move on a run with `notes log` ([operate-a-run](operate-a-run.md)).

## The moves

How an agent runs decides its moves, and its role does not.

| The agent runs as | Moves |
|---|---|
| A session on this machine ([sessions](sessions.md)) | Read each tool call as it happens in `turns/<n>.jsonl`. `send` a follow-up, and a busy session takes it when its turn ends. `interrupt`, then `send` a new direction: the conversation survives the interrupt. `close`. |
| A workflow step on this machine (`pi`, `claude`, `codex`) | `kill --run <run-dir> --step <coord> --reason TEXT` ends one step's attempt and its process tree within one poll, and the other steps run on ([ohflow](ohflow.md#run-it)). The killed step records `deferred` with your reason, and no retry or auto-resume pass starts it again. When the run stops, `run --resume <run id>` starts it again and passed steps stay cached. The new attempt reads your reason under "What failed last time" in its position block, so a reason that names the right move redirects the step with no brief edit. For a larger change, edit its brief before the resume. The edit makes a new revision with its own budget ([ohflow](ohflow.md#the-run-log-is-the-truth)). The engine also ends a step through its own limits: execution timeout, stall and command cap. |
| A `durable` step, on `box: local` or an ssh box | `kill` ends the attempt and the host's step with it, and the resume starts a fresh conversation. To keep the conversation, stop the supervisor and resume instead: the step reattaches, the host replays its conversation, and the model sees its killed command as interrupted. A new direction reaches it only through a brief edit after the attempt ends. |
| A step in a Cloudflare container (`pi-cloud`, `claude-cloud`, `codex-cloud`) | `kill` posts `abort`, so the container stops with the attempt, and the resume starts a fresh conversation. A stop and resume of the supervisor reattaches to the container instead. Every limit is an execution timeout set before `go` ([monitor-a-run](monitor-a-run.md#at-hand-over-write-the-bill)), because a limit relayed during a run reached the steps of 15.11.2026 after they ended. An execution timeout posts the same `abort`. A retry after a failure starts a fresh conversation. |
